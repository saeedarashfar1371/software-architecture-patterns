# Event-driven Architecture (event-driven.md)

## Definition
Components communicate through events, often asynchronously.

## Key Characteristics
- Event producers and consumers
- Message queues or brokers
- Decoupled components

## Advantages
- Highly decoupled and scalable
- Suitable for reactive and real-time systems

## Disadvantages
- Complexity in event management
- Debugging can be challenging
- Ordering and delivery guarantees can be tricky

## Use Cases
- Real-time applications
- IoT systems
- Notification systems

## Key Points
> Event-driven systems are powerful for scalability and responsiveness but require robust event handling strategies.
